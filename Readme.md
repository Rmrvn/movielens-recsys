# MovieLens-1M: рекомендательная система от baseline до двухэтапной схемы

Учебный проект по рекомендательным системам на открытых данных MovieLens-1M. Путь от простого baseline до двухэтапной схемы «кандидаты + ранкер»: честный сплит по времени, метрики качества, собственные реализации ItemKNN и ALS, подбор гиперпараметров на валидации, ранкер на CatBoost и юнит-тесты.

**Главный результат.** Двухэтапная схема (ALS + CatBoost) на отложенной по времени тестовой выборке даёт Recall@10 = 0,083 против 0,043 у рекомендаций «самое популярное» (почти вдвое) и NDCG@10 = 0,112 против 0,079.

## Данные

[MovieLens-1M](https://grouplens.org/datasets/movielens/1m/) (GroupLens, Университет Миннесоты): 1 000 209 оценок от 6 040 пользователей для 3 706 фильмов, 2000–2003 годы.

- Оценки превращаются в **неявные положительные взаимодействия**: оценка ≥ 4 означает «подошло» (575 281 взаимодействие, 57,5%). Так мы имитируем реальные продукты, где есть клики и покупки, а не оценки «нравится/не нравится».
- Из выборки убраны пользователи, у которых меньше 5 положительных взаимодействий (осталось 6 034 пользователя из 6 040).
- Заполненность матрицы «пользователь × фильм» всего 4,47%, популярность фильмов сильно неравномерна (длинный хвост).

## Постановка задачи и разбиение

По истории положительных взаимодействий пользователя предсказать, какие фильмы он оценит высоко **позже**.

- **Сплит по времени внутри пользователя:** последние 20% положительных взаимодействий каждого пользователя идут в test, остальные в train (train 457 813, test 117 459; доля теста 20,4% из-за округления вверх). Такой сплит исключает утечку данных из будущего; в коде есть проверка, что внутри каждого пользователя train не позже test.
- Лишь 0,09% тестовых взаимодействий приходится на фильмы, которых нет в train.
- Для подбора гиперпараметров train делится по времени ещё раз на `train_core` и `valid`. **Тест на этапе настройки не используется** и применяется для финальной оценки.
- При равных временных метках порядок взаимодействий фиксируется по `item_id`, поэтому результат воспроизводим.

## Метрики

- **Recall@K** — доля релевантных фильмов из теста, найденных в топ-K.
- **NDCG@K** — то же с учётом позиции: попадание выше в списке стоит больше.
- **Охват каталога** — доля фильмов, попавших хотя бы в один список рекомендаций.
- **Средняя популярность рекомендаций** — сколько в среднем оценок у рекомендованных фильмов.

Пользователь без рекомендаций получает 0, чтобы модель не выигрывала, пропуская сложных пользователей.

## Модели

1. **Popular** — всем самое популярное из ещё не виденного (baseline).
2. **ItemKNN** — сходство фильмов по косинусу на матрице «пользователь × фильм» (разреженные матрицы SciPy, расчёт батчами). Оценка кандидата — сумма его сходств с фильмами из истории пользователя.
3. **ALS** — матричная факторизация для неявной обратной связи (Hu, Koren, Volinsky), **написана с нуля на NumPy**; в тестах быстрая формула шага сверяется с прямой формулой.
4. **Двухэтапная схема** — ALS отбирает 100 кандидатов на пользователя, CatBoost переупорядочивает их.

### Двухэтапная схема

- **Признаки кандидата:** ранг и оценка ALS, оценка и ранг ItemKNN (внутри списка пользователя), логарифм популярности фильма, логарифм активности пользователя. Все признаки считаются **только по истории**; тест в `tests/test_ranking.py` проверяет, что метки на признаки не влияют.
- **Метки:** 1, если пользователь потом действительно оценил фильм высоко.
- **Два слоя времени:** ранкер обучается на таблице, построенной по `train_core` с метками из `valid`, а проверяется на таблице по всему `train` с ответами из `test`.
- **Ранкер:** `CatBoostClassifier` (до 500 деревьев, глубина 6, шаг 0,1), ранняя остановка по AUC на отдельных контрольных **пользователях** (не на строках, чтобы не было утечки между похожими строками одного пользователя); лучшая итерация 201.
- Потолок схемы: кандидаты содержат в среднем 46,8% релевантных фильмов (Recall@100 на валидации).

## Результаты (тестовая выборка)

| Модель | Recall@10 | NDCG@10 | Recall@20 | NDCG@20 | Recall@50 | NDCG@50 |
|---|---|---|---|---|---|---|
| Popular | 0,0426 | 0,0791 | 0,0815 | 0,0869 | 0,1550 | 0,1095 |
| ItemKNN | 0,0666 | 0,1044 | 0,1114 | 0,1138 | 0,2131 | 0,1473 |
| ALS (настроенный) | 0,0759 | 0,1021 | 0,1361 | 0,1204 | 0,2687 | 0,1672 |
| **ALS + CatBoost-ранкер** | **0,0832** | **0,1119** | **0,1450** | **0,1297** | **0,2775** | **0,1756** |

Ранкер против ALS без ранкера: Recall@10 +9,6%, NDCG@10 +9,7%, Recall@50 +3,3%. Выигрыш больше на коротких списках, потому что набор кандидатов тот же и меняется только порядок.

**Разнообразие рекомендаций** (k = 50, ALS с параметрами по умолчанию: 32 фактора, `reg=100`, `alpha=20`):

| Модель | Охват каталога | Средняя популярность |
|---|---|---|
| Popular | 7,3% | 1364 |
| ItemKNN | 23,9% | 1192 |
| ALS | 43,5% | 838 |

### Подбор гиперпараметров ALS

Перебор по сетке из 27 вариантов (факторы {16, 32, 64} × `reg` {30, 100, 300} × `alpha` {10, 20, 40}) на валидации по Recall@50. Лучший вариант: 64 фактора, `reg=100`, `alpha=10`. Меньшее `alpha` стабильно лучше; лучшие значения лежат на краю сетки (наименьшее `alpha`, наибольшее число факторов).

### Важность признаков ранкера

`als_score` 37,1; `knn_score` 15,6; `item_pop` 15,1; `knn_rank` 12,5; `als_rank` 12,0; `user_activity` 7,8. Сигналы ItemKNN вместе — вторая по величине группа: ранкер объединяет достоинства обеих моделей.

## Как запустить

```powershell
git clone https://github.com/Rmrvn/movielens-recsys.git
cd movielens-recsys
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Скачайте [ml-1m.zip](https://files.grouplens.org/datasets/movielens/ml-1m.zip) и распакуйте так, чтобы файл лежал по пути `data/ml-1m/ratings.dat` (папка `data/` не хранится в репозитории).

Юнит-тесты:

```powershell
python -m pytest
```

Ноутбуки по порядку (ядро `.venv`):

| Ноутбук | Содержание |
|---|---|
| `01_data_exploration` | знакомство с данными |
| `02_split` | фильтрация и сплит по времени |
| `03_popular_baseline` | baseline «популярное», влияние фильтра просмотренного |
| `04_item_knn` | ItemKNN, охват каталога |
| `05_als` | ALS, сравнение моделей |
| `06_tuning` | валидационная выборка и подбор гиперпараметров |
| `07_candidates` | кандидаты и признаки для ранкера |
| `08_ranker` | CatBoost-ранкер и итоговая оценка |

Все расчёты в ноутбуках выполняются на реальных данных MovieLens-1M. Юнит-тесты используют маленькие вручную составленные таблицы, где ожидаемый ответ можно посчитать в уме: они проверяют корректность кода, а не качество моделей.

## Ограничения

- Один сплит и один запуск (один `seed`); устойчивость выигрыша на 3–10% статистически не проверялась.
- Сплит по времени сделан внутри пользователя, а не по общей календарной дате.
- ItemKNN не настраивался, а ALS и ранкер настраивались; для строгого сравнения нужно настроить и его.
- Потолок двухэтапной схемы ограничен кандидатами от одной модели (ALS).
- Только офлайн-метрики; влияние на пользователей в продукте не измерялось.
- Порог положительного взаимодействия (оценка ≥ 4) выбран произвольно; MovieLens-1M — старые данные (2000–2003), не похожие на современные потоки событий.
- Новые пользователи без истории (холодный старт) не обрабатываются: ItemKNN и ALS ничего им не предлагают.

## Что можно улучшить

- Признаки по жанрам и году фильма, временные признаки.
- Целевая функция ранжирования (например, YetiRank) вместо классификации.
- Кандидаты из нескольких источников (ALS, ItemKNN, популярное) для повышения потолка.
- Настройка ItemKNN и ранкера на валидации, оценка разброса по нескольким `seed` и бутстрэпом.
- Трансформерная модель последовательных рекомендаций (SASRec).
- Дизайн A/B-теста для проверки ранкера в продукте.
